# HTML Dashboard Import
## BI Design Studio · Import HTML (`/import`)

Turns a dashboard built as a web page, for example one generated by an AI assistant or hand-coded, into an editable design. The flow is:

**upload → review (converted design next to the original, list of what was found) → Open in editor → adjust → Export → Power BI project (PBIP)**

No AI is involved. The conversion uses deterministic rules (the separate AI Design Assistant, `docs/AI_ASSISTANT.md`, is the only feature that uses AI).

## How it works

1. **Read the file.** One `.html`/`.htm` file of at most 5 MB, read in the browser. Nothing is uploaded to a server.
2. **Render it in a sandbox.**
   - The page is shown in an `<iframe sandbox="allow-scripts">` at 1440 × 900, so its chart libraries draw normally.
   - The frame has an opaque origin, so it has no access to the studio, its storage or cookies. It cannot navigate the app, open pop-ups or submit forms.
   - The page may load its own scripts, such as chart libraries from a CDN, from the internet.
3. **Collect.**
   - A collector script is injected into the page. It waits until rendering settles: 1.5 s minimum, quiet DOM for 1 s, 8 s maximum.
   - It then reads the chart libraries' own data (not pixels), plus tables, KPI cards, filters, headings, images, their positions and the page colours.
   - It posts the result to the studio with a per-import nonce. The studio accepts only messages from that frame with that nonce, and validates the payload against a strict schema with size limits (`rawExtraction.ts`).
4. **Convert.** Pure, unit-tested functions map everything to design visuals, the 12-column grid and a theme (see below). The result is validated like any imported design.
5. **Review and open.**
   - The design is saved locally and opens in the editor.
   - It is marked `source: { kind: "html-import", … }`, so notices and exports say "values copied from your file" instead of "fictional sample data".

## What converts

| Found in the page | Becomes |
| --- | --- |
| **Chart.js, ECharts, Plotly, Highcharts, ApexCharts** charts | Bar (vertical or horizontal), stacked or 100 % stacked bar, line, area (stacked), combo (bars and lines, secondary axis), pie, donut, gauge; a Plotly number indicator becomes a KPI card |
| Series data, category labels, series colours, titles, legend visibility, smooth lines | Kept |
| Number formats | Inferred from rendered axis labels and format strings (`$`, `€`, `£`, `%`, `K`/`M`), titles and series names. Ratios shown as percentages (0.12 → 12 %) are converted to percent numbers |
| KPI cards: large numbers such as `$2.45M`, `18,420`, `3.8%`, `14.5 hrs` | KPI card with the label, the change ("▲ 12.5 % vs last month"), its direction and polarity (red increase = lower is better), the target ("Target: 4.0 %") and a sparkline (small Chart.js/ECharts chart or SVG polyline) |
| `<table>` | Table; columns that are at least 60 % numeric become typed number, currency or percent columns |
| `<select>`; groups of 2–8 toggle buttons with one active | Slicer (dropdown, list or buttons) |
| `h1`–`h6` and large standalone text | Text (heading, subheading, body or caption) |
| `<img>` | Image: the picture is copied when it is embedded; otherwise a placeholder |
| Layout | Positions mapped to the 12-column grid, keeping columns, rows and relative sizes. Overlaps are moved down. Long pages become one tall page (up to 4,000 px); longer pages are split into several pages |
| Colours | A light or dark base theme with overrides for page and card background, text, muted text, border, corner radius, primary colour and chart palette |

## Charts drawn without a chart library

AI tools often draw charts directly as SVG shapes or with HTML/CSS. Such charts are **recognised from their geometry** and become real visuals of the same type (`convert/drawings.ts`):

| Drawing | Recognised as |
| --- | --- |
| SVG `rect`s or rectangle `path`s (including rounded, Recharts-style) sharing a baseline or a left edge | Bar chart, vertical or horizontal; grouped by colour into series; stacked when segments share a slot |
| SVG `polyline`s and `path`s (straight or curved) | Line chart; closed filled paths become an area chart; bars and lines together become a combo chart |
| SVG arc `path`s, or `circle`s with `stroke-dasharray` | Pie or donut (donut when slices have an inner edge or are dashed rings) |
| CSS `conic-gradient(...)` | Pie, or donut when it has a centre hole (pseudo-element, child or radial gradient) |
| Rows of `<div>` bars (progress bars in tracks, or columns of bars) | Horizontal or vertical bar chart |

Values are taken in this order of preference. The import report says which method was used:
1. **Axis scale:** tick labels next to the plot give the pixel-to-value scale. Values are measured ("check them").
2. **Value labels:** numbers shown on or next to the bars, or in the legend, such as "Marketing 50 %". Exact.
3. **Progress tracks:** fill width ÷ track width, in percent.
4. **Pie shares:** percent of the circle.
5. **Relative sizes:** when the chart shows no scale or labels at all. Largest = 100, flagged "replace with the real values".

Category names come from the axis labels or row labels, and series names and colours from the legend (HTML swatches or small SVG markers). In a combo chart the line uses the bars' scale; it moves to a secondary axis only when its values have a clearly different scale.

## What does not convert (and what happens instead)

| Case | Result |
| --- | --- |
| Library chart types with no design equivalent (scatter, bubble, radar, heatmap, maps, treemap, …) | A **picture** of the chart, flagged "Picture only" |
| Drawn charts whose shapes match no supported type (scatter plots, maps, illustrations) | A **picture** (SVG pictures keep their CSS colours), or a placeholder |
| Charts drawn on a `<canvas>` by an unknown library | A **picture**; a canvas holds pixels only, with no shapes to measure |
| ApexCharts charts without a `chart.id` | Not in Apex's registry, so they come in as pictures |
| Pages that load their data or scripts from local files next to the HTML | Those files are missing in the sandbox; the affected charts don't draw |
| Pages that need storage, cookies or log-in | Blocked by the sandbox |
| `div`-based tables, CSS-only bar charts, maps | Not detected |
| Interactivity (tooltips, drill-down, cross-filtering) | Not carried over |

Every element is listed in the import report as **Converted**, **Simplified** (for example "3 missing values set to 0" or "Only the first 60 categories were kept"), **Picture only** or **Placeholder**. Items that need attention are listed first.
